# deckgen

Product generate compiles an editable SlimPPT `Presentation` — the same IR chat tools mutate (text, shapes, charts, tables, image backgrounds). That IR already serializes to OOXML; there is no separate SVG toolchain.

Emit writes a real slide master (`pres.masters[]`) with theme background, type styles, standard placeholders, and one layout per catalog id (plus any extra canvas names and Blank). Slides get `layoutRef`. Solid pages inherit `master.background` so Master View / new-slide / theme bg stay linked. Photo canvases keep their image background and set `showMasterSp: false` so master chrome does not sit on the photo. Canvas art stays on the slide — layouts are placeholder skeletons, not a stamp of unique page shapes.

## Live path (API key)

Reviewed outline → per-page visual **job** (hint, not a skeleton lock) → fetch real photos first → LLM authors each page as a complete canvas JSON → snap (grid, type ramp, real src only) → emit.

- Photography-as-canvas: feature pages use `slide.background` `fit: cover` plus a scrim. Empty image frames are dropped.
- Deck palette is authored with the canvases (`systemId` + hex). A brand hex in extra notes can pin `palette.accent`. Named ColorTheme ids are optional seeds, not a wizard picker. Pairing tables apply to the no-key fill fallback.
- Palette is a *system*, not seven free hex values: `harmonizePalette` (`color-theme.ts`) nudges every role to `PALETTE_FLOORS` (ink ≥ 7:1 / muted ≥ 4.5:1 / accent ≥ 1.5:1 on bg; surface and accentSoft separated from bg and readable under ink; line visible), preserving hue and the author's string when nothing moved. If only bg / ink / accent are authored, the rest is derived from those three. Per element, `ensureTextReads` (`apply-theme.ts`) re-checks each text token against its real backdrop (panel, solid / linear field, scrimmed photo) and swaps to the best-contrast token; `onRoleText` picks type colour on accent fills (bands, hubs, table headers). Scrims default to the *dark* token of the system (`ink` on light paper, `bg` on dark paper); text shadows are cast in the darker token.
- Art type: one display-size text per anchor page may carry `treatment: gradient | outline | shadow | glow`. `snap` normalizes aliases, gates by system bans (`resolveTreatment`), keeps at most one per page, and applies the system's `canvas.displayTreatment` when the author set none. `emit` writes outline as `<a:noFill/>` + `textOutline`, gradient as a run `fill` whose far stop still clears 3:1 on the paper; `validate` / `art-director` read hollow runs through `effectiveRunColor` so QA never flood-fills an outlined title.
- Motion: one animation unit enters together (same effect, same start). A chain (kicker, title, subtitle, a single close) auto-plays after one click; a spread series (peer cards, steps, agenda rows, an unframed bullet list) waits for a click per item. Device tiles carry `animUnit` (`kpis.kpi0`, `steps.step2`). Plates keep text that overlaps them or overhangs by at most 24px. Page-sized fields stay put.
- Carriers: text, rect, ellipse, line, overlay, chart, table, image. Radius, shadow, and linear paint are allowed on this path.
- One JSON call for the whole deck, plus one repair. No extra wizard steps. The repair is page-scoped when every finding names its pages (`repairScope` in `deckgen-adapter.ts`: only those pages are re-authored, with a one-line digest of the untouched pages for folio / header consistency); a deck-level finding without `pages`, or a scope covering ≥ 60 % of the deck, falls back to a full pass. Either way the result is merged per page against the first pass (`mergeCanvasPages`: fewer findings wins) so a repair cannot regress a page that was fine.
- Reading load: `reflect-canvas` caps copy below h2 per page (`READING_CAP` dense 320 / default 260 / breathing 210 CJK-equivalent characters, ×0.7 on a photo canvas; ≤ 16 blocks) and floors dense pages at 22 % field coverage. Content checks: title count vs items ("四个" over five tiles), unbalanced compare planes, folio numerals counting up at one size.
- Design Brief (`brief.ts`): the organizer emits `mode / systemId / paletteIntent / motif` per deck and `coreMessage / relationships / rhythm / carrier / composition` per page. `composition` (`header-stack | split | statement | full-bleed | grid | band | sidebar`) is assigned so no two consecutive pages share one (`jobs.ts` fills gaps and breaks runs); the author prompt carries it per page and `reflect-canvas` checks it, plus a header-run gate (same top-third text stack on ≥ 3 pages) and a readability floor (running copy < 13px).
- Type anchors are the system's, not the author's: on content pages (not cover / close / section / quote / claim, not anchor rhythm, not statement / full-bleed) snap forces the page title to `h1` (`h2` only if two lines of h1 won't fit) — by slot name when there is one, else the largest word-text in the top third (`findContentTitle`, numerals / KPI values excluded). `reflect-canvas` keeps one deck-level `coherence` finding as a backstop for paths where snap didn't see the briefs.
- Photos: organizer asks for `imageIdea` on photo pages and roughly one in every 3–4 content pages; `acquire-page-images.ts` caps the deck at cover + close + one per ~3 content pages, trimming least-important first.
- Agenda / 目录: outline hint `agenda` → job `agenda` (`jobs.ts`; the outline prompt asks for one right after the cover on decks ≥ 8 slides or ≥ 2 sections). The author writes one `agendaList` device (`devices.ts`: numeral + title + body rows, two columns from six rows) whose `items[].target` is a 1-based page. `resolveAgendaTargets` (`snap.ts`) repairs targets against the deck — explicit if it names another page, else by title match, else the k-th section page after the agenda, else the k-th content page — and every row primitive carries `link`, which `emit` turns into `shape.hyperlink { kind: "slide" }` (`ppaction://hlinksldjump`; the player, serializer, and editor dialog already handle it). Any element may carry `link:<page>` ("↩ contents" marks). Chat has the same via `insertAgendaSlide`.
- Folio (page numerals) is a deck decision, not a habit of the model: `DeckBrief.folio` comes from the user's words (`folioFromNotes`: 加页码 / no page numbers), else `GuidanceInput.pageNumbers`, else the organizer's brief, else `defaultFolio(mode, pageCount)` (briefing / instructional ≥ 6 pages, showcase / narrative ≥ 14, otherwise ≥ 10). The author prompt states the decision; snap enforces it (`applyFolio`): `false` strips every bare numeral outside a device, `true` numbers every content page (cover / close / anchor pages excluded) at one size — the author's numeral if present, else a caption-size `folio` slot in the bottom margin corner that is free. `reflect-canvas` still checks count-up and one size.
- Photographs are a deck decision too: `DeckBrief.photoRhythm` ∈ anchors / bookends / editorial / none comes from the user's words (`photoRhythmFromNotes`: 不要配图 / photo-heavy), else the organizer's brief, else `defaultPhotoRhythm(mode)` (showcase → editorial, otherwise anchors). `applyPhotoRhythm` (jobs.ts) enforces it before image acquisition: under anchors every type-led anchor page (cover, section openers, hero claims, close) becomes carrier=photo with a full-bleed / statement composition and every interior page loses its photo; bookends keeps cover + close only; none strips all; editorial leaves the per-page picks. `acquirePageImages` never caps a carrier=photo page, prefers stock hits whose average colour matches the deck tone (`pickBestHit` tone term — one pink picture among dark ones reads as two decks), and `fillMissingPhotos` lends the cover's photograph to a photo page whose fetch missed rather than dropping that one page to paper. An organizer answer of `none` cannot override a brief that asked for photographs (`notesWantPhotos`: 全屏摄影 / full-bleed photography → anchors). A photo page without an `imageIdea` searches the deck's visual world — the cover's idea — not `topic + title` (`photoQueryFor`), because stock for a product title returns app screenshots whose text fights the title set on top; `pickBestHit` also ranks hits whose alt text says the picture is lettering (book spines, signs, screenshots) behind plain ones.
- Copy is a deck decision as well. `generate/copy-voice.ts` holds one `COPY_VOICE_BLOCK` injected into every stage that writes words (outline, organizer, canvas author, chat): titles say what the page shows, no "X 不是 Y" antithesis beyond one per deck, no launch-copy verbs (赋能 / seamless / unlock), no copy about the slide's own design (scrim / WCAG / folio). `lintCopyVoice` is the deterministic check; `reflectCanvas` turns its hits into `content` findings (≤ 3 per page, plus one deck-level finding when more than one title is negation-framed) so the repair pass rewrites them.

## Debugging a live run

`pnpm smoke:ai` dumps the model's raw canvas JSON and the organized outline to `$TMPDIR/slimppt-smoke/`; `pnpm replay:canvas [dump] [outline]` replays a dump through normalize → zod → snap/reflect offline (no LLM) and prints the same `[canvas]` block plus every finding — the loop for turning a live drop / gate finding into a normalizer or gate fix. A page-scoped repair dump carries `repairPages`; the replay splices it into the latest author dump beside it.
